Cómo funciona credentials: 'include' con Cookie HttpOnly

Fase 1
Login — Obtener la Cookie
⚛ Frontend (React)
↔ Red
⟐ Backend (CodeIgniter 4)
1
Frontend — Tu Código
Usuario escribe email y password en el formulario de login y presiona "Ingresar"
const res = await fetch('https://tu-servidor.com/auth/login', { method: 'POST', credentials: 'include', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ email, password }), });
POST /auth/login
{ email, password }
2
Backend — Auth Controller
Busca el usuario en la DB y verifica el password con bcrypt
$user = $userModel->where('email', $email)->first(); if (!$user || !password_verify($password, $user['password'])) { return 401; // Credenciales inválidas }
3
Backend — Genera JWT
Crea un token JWT con el ID, nombre y rol del usuario, firmado con JWT_SECRET del servidor
$payload = [ 'sub' => $user['id'], // quién es 'role' => $user['role'], // qué puede hacer 'exp' => time() + 3600, // cuándo expira ]; $jwt = JWT::encode($payload, $key, 'HS256');
4
Backend — Set-Cookie
Empaqueta el JWT dentro de una cookie HttpOnly y la incluye en los headers de la respuesta HTTP
$this->response->setCookie([ 'name' => 'auth_token', 'value' => $jwt, // el JWT va AQUÍ 'httponly' => true, // ⛔ JS no puede leerla 'secure' => true, // 🔒 solo HTTPS 'samesite' => 'None', // 🌐 cross-site ]);
5
Navegador — Automático
El NAVEGADOR (no tu código) lee el header Set-Cookie y guarda la cookie internamente en su almacén privado.

Tu JavaScript NO puede ver esta cookie. No está en localStorage, no está en ninguna variable, no aparece en document.cookie.
Response HTTP 200
+ Header: Set-Cookie
🔑
Punto clave: El JWT viaja del backend al navegador como un header HTTP (Set-Cookie), NO como dato JSON. Tu código React solo recibe { message: "Login exitoso", user: {...} }. La cookie la maneja el navegador de forma completamente invisible.
🍪
Fase 2
Request a la API — La Cookie Viaja Sola
⚛ Frontend (React)
↔ Red
⟐ Backend (CodeIgniter 4)
6
Frontend — Tu Código
Llamas a la API normalmente. No envías tokens, ni headers de auth, ni credenciales. Solo credentials: 'include'.
// Esto es TODO lo que escribes const data = await fetch('https://tu-servidor.com/proxy/items', { credentials: 'include', // ← le dice al NAVEGADOR }); // "adjunta tus cookies"
7
Navegador — Automático
Al ver credentials: 'include', el navegador busca en su almacén de cookies, encuentra auth_token para ese dominio y la adjunta automáticamente al request HTTP.
// Lo que el NAVEGADOR construye internamente: GET /proxy/items HTTP/1.1 Host: tu-servidor.com Cookie: auth_token=eyJhbGciOiJIUzI1NiJ9... ← AUTOMÁTICO Origin: https://tuusuario.github.io
GET /proxy/items
+ Cookie: auth_token=JWT
⚠️
credentials: 'include' NO pasa credenciales. Es una instrucción que dice "navegador, tienes permiso de enviar tus cookies". Sin esta línea, el navegador NO envía cookies en peticiones cross-origin (distinto dominio) — es una protección de seguridad del navegador.
8
Backend — Filtro CORS
Verifica que el Origin sea https://tuusuario.github.io. Si no coincide → 403.
$origin = $request->getHeaderLine('Origin'); if ($origin !== getenv('ALLOWED_ORIGIN')) { return 403; // Origen no permitido }
9
Backend — Filtro AuthJWT
Extrae el JWT de la cookie, verifica la firma con JWT_SECRET, comprueba que no esté expirado y que el usuario esté activo.
$token = $request->getCookie('auth_token'); $decoded = JWT::decode($token, new Key($key, 'HS256')); // $decoded->sub = 1 (ID usuario) // $decoded->role = "admin" (permisos)
10
Backend — Proxy Controller
Verifica el rol del usuario, luego llama a la API externa con la API_KEY privada que solo el servidor conoce.
// La API_KEY nunca sale del servidor $response = $client->get($this->apiUrl . '/items', [ 'headers' => [ 'Authorization' => 'Bearer ' . $this->apiKey, ], ]);
11
Frontend — Recibe Datos
Tu código recibe la respuesta JSON con los datos. En ningún momento tu JavaScript vio, tocó o manipuló el JWT ni la API_KEY.
const items = await data.json(); // [{ id: 1, name: "Item 1" }, ...] // ✅ Datos listos — sin haber tocado credenciales
Response 200
{ data: [...] }
✅
Resultado: Tu frontend obtuvo los datos de la API externa sin conocer ni la API_KEY ni el JWT. Las credenciales viajaron de forma invisible entre el navegador y tu servidor Apache.
🛡
Fase 3
¿Qué pasa sin login? — Atacante con Postman
🔓 Atacante
↔ Red
⟐ Backend (CodeIgniter 4)
1
Atacante — Postman / cURL
Intenta llamar al proxy directamente sin cookie
curl https://tu-servidor.com/proxy/items // No tiene cookie auth_token // No conoce el JWT_SECRET para fabricar una
GET /proxy/items
(sin cookie)
2
Backend — Filtro AuthJWT
No hay cookie → No hay JWT → RECHAZADO
$token = $request->getCookie('auth_token'); // $token = null return response()->setJSON([ 'error' => 'No autenticado' ])->setStatusCode(401); // ⛔ BLOQUEADO
3
Atacante — Rechazado
Recibe error 401 No autenticado. No puede acceder a la API. No puede fabricar un JWT válido porque no conoce el JWT_SECRET.
// Respuesta: { "error": "No autenticado" } // 401 // ¿Puede fabricar un JWT? // NO — necesitaría el JWT_SECRET que está en // el .env del servidor — inaccesible.
401 Unauthorized
⛔ BLOQUEADO
⛔
El atacante no puede: ① Inspeccionar el JS para encontrar tokens (no hay ninguno) · ② Fabricar un JWT (no conoce JWT_SECRET) · ③ Robar la cookie con XSS (es HttpOnly) · ④ Usar la cookie desde otro sitio (SameSite + CORS) · ⑤ Interceptar en tránsito (Secure = solo HTTPS)
⚡
Resumen
Con vs Sin credentials: 'include'

❌ Sin credentials: 'include'

fetch('https://tu-servidor.com/proxy/items') // Lo que viaja en el request HTTP: GET /proxy/items Host: tu-servidor.com // ← NO hay cookie // ← El navegador NO la adjunta // Backend: "¿Quién eres?" → 401

El navegador tiene la cookie guardada pero no la envía porque no le diste permiso. En peticiones cross-origin, el navegador protege las cookies por defecto.

✅ Con credentials: 'include'

fetch('https://tu-servidor.com/proxy/items', { credentials: 'include', }) // Lo que viaja en el request HTTP: GET /proxy/items Host: tu-servidor.com Cookie: auth_token=eyJhb.. ← ¡Automático! // Backend: JWT válido → 200 + datos

Le dices al navegador: "envía tus cookies". Él las adjunta automáticamente. Tu JavaScript nunca ve ni toca el JWT.
