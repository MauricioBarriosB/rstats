02 — Flujos de Autenticación
● Flujo de Login
1

Usuario envía credenciales

POST /auth/login con email y password en JSON

2

Backend valida credenciales

Busca user en DB, compara con password_verify()

3

Genera JWT con datos del usuario

Payload: sub, role, exp — firmado con JWT_SECRET

4

Responde con cookie HttpOnly

Set-Cookie: auth_token=JWT; HttpOnly; Secure; SameSite=Strict

5

Navegador almacena la cookie

Automático e invisible para JavaScript — imposible de leer con document.cookie

● Flujo de Request Protegido
1

Frontend hace fetch con credentials

fetch(url, { credentials: 'include' }) — cookie viaja automáticamente

2

Filtro CORS valida el origen

Solo acepta requests desde tuusuario.github.io

3

Filtro JWT extrae y valida token

Lee cookie → decodifica JWT → verifica firma y expiración

4

Controlador verifica permisos

Según $request->user->role permite o bloquea la operación

5

Proxy llama a API externa

Inyecta API_KEY del .env del servidor y reenvía la respuesta

03 — Capas de Seguridad (Pipeline de Validación)
🌐

Capa 1 — CORS + Validación de Origen

Access-Control-Allow-Origin: tu dominio exacto · Access-Control-Allow-Credentials: true

Falla → 403
🍪

Capa 2 — Cookie HttpOnly + Secure + SameSite

JavaScript no puede leer la cookie · Solo se envía por HTTPS · No se envía desde otros sitios

Falla → 401
🔑

Capa 3 — JWT Válido (firma + expiración)

firebase/php-jwt verifica con JWT_SECRET del servidor · Token expira en 1h

Falla → 401
👤

Capa 4 — Control de Roles (RBAC)

admin: CRUD completo · editor: crear y editar · viewer: solo lectura

Falla → 403
⏱

Capa 5 — Rate Limiting por IP

CodeIgniter Throttler · Máx 60 req/minuto por IP

Falla → 429
04 — Propiedades de la Cookie
🍪 Set-Cookie: auth_token
httponly = true
HttpOnly
JavaScript no puede acceder a la cookie. Bloquea robo por XSS vía document.cookie o localStorage.
secure = true
Secure
Solo se transmite por HTTPS. Previene interceptación en redes inseguras (man-in-the-middle).
samesite = Strict
SameSite=Strict
No se envía en requests cross-site. Bloquea ataques CSRF desde sitios maliciosos.
expire = 3600
Max-Age: 1 hora
Token de corta duración. Si se compromete, la ventana de exposición es limitada.
path = /
Path: /
Disponible para todas las rutas del backend proxy.
domain
tu-servidor.com
Cookie asociada exclusivamente al dominio de tu servidor Apache.
05 — Vectores de Ataque Bloqueados
🛡

XSS (Cross-Site Scripting)

Aunque inyecten JS malicioso, no pueden leer la cookie HttpOnly ni enviarla a otro servidor.

BLOQUEADO POR HttpOnly
🛡

CSRF (Cross-Site Request Forgery)

SameSite=Strict impide que la cookie se envíe desde formularios o links en otros sitios.

BLOQUEADO POR SameSite
🛡

Inspección de JS (DevTools)

No hay tokens, API keys, ni credenciales en el código JavaScript del frontend.

BLOQUEADO POR DISEÑO
🛡

Postman / cURL sin sesión

Sin login válido no hay cookie JWT. Sin cookie, el proxy responde 401.

BLOQUEADO POR JWT + Cookie
🛡

Fuerza bruta de login

Rate limiting bloquea IPs con demasiados intentos. Passwords hasheados con bcrypt.

BLOQUEADO POR Rate Limit
🛡

Man-in-the-Middle

Cookie Secure solo viaja por HTTPS. Imposible interceptar en redes públicas.

BLOQUEADO POR Secure + HTTPS
